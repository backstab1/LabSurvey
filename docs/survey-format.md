# Формат анкеты SurveyLAB (formatVersion 2)

Анкета — один JSON-объект. Респондент видит **один вопрос на экране**. Вопросы сгруппированы в **блоки** (для порядка; своей логики у блоков нет).
Вся логика задаётся на вопросах: **условие показа** и **действия** перед показом / после ответа.
Полный пример: `examples/demo.json`.

## Структура

```json
{
  "formatVersion": 2,
  "title": "Название, которое видит респондент",
  "description": "Для команды (необязательно)",
  "settings": { "showProgress": true, "allowBack": true, "allowEarlyFinish": false },
  "css": "",
  "scripts": { "init": "" },
  "blocks": [
    { "id": "B1", "title": "Скринер", "questions": [ ... ] },
    { "id": "B2", "title": "Основной блок", "questions": [ ... ] }
  ]
}
```

- `id` блоков и вопросов: латиница, цифры и `_`, начинается с буквы, до 32 символов. Все ID уникальны (без учёта регистра), ID блока не совпадает с ID вопроса.
- ID вопроса = имя переменной в выгрузке (Excel/SPSS): короткие ID вроде `S1`, `Q5`, `D2`.
- Зарезервированы: `resp_id`, `status`, `started_at`, `completed_at`, `duration_sec`, `ip`, `user_agent`, `is_test`, `version`.
- `title` блока (необязательно) показывается респонденту над вопросами блока.
- `order` блока: `"random"` — вопросы блока в случайном порядке, `"rotate"` — ротация; порядок свой у каждого респондента и не меняется при возврате. Вопрос с `"fixed": true` остаётся на своём месте, скрытые переменные не перемешиваются. Вопросы такого блока не должны ссылаться друг на друга (условия, подстановки, перенос) — иначе закрепите их. Переход к блоку ведёт к его первому вопросу в порядке респондента.
- **Коды** вариантов — целые числа, уникальные внутри списка. Принято: 97 — «Другое», 98 — «Отказ», 99 — «Затрудняюсь ответить».
- Анкеты старого формата (`formatVersion: 1`, `pages`) при импорте переводятся автоматически: страница → блок, переходы страницы → действия последнего вопроса.

### settings

| Поле | По умолчанию | Что делает |
|---|---|---|
| `showProgress` | `true` | Полоса прогресса |
| `allowBack` | `true` | Кнопка «Назад» |
| `allowEarlyFinish` | `false` | Кнопка «Завершить опрос досрочно» (статус «Завершён досрочно») |
| `showQuestionNumbers` | `false` | «Вопрос 3» над текстом (номер по порядку показа респонденту) |
| `enterSubmits` | `true` | Enter в однострочном поле нажимает «Далее» |
| `autoNext` | `false` | Автопереход по умолчанию для single / dropdown / scale (вопрос может переопределить `autoNext: false`) |
| `noPaste` | `false` | Запрет вставки по умолчанию для открытых вопросов |
| `completeMessage` | «Спасибо! Ваши ответы сохранены.» | Текст после завершения. Подстановки `{{Q1}}`, `{{param.x}}` работают |
| `screenoutMessage` | стандартный | Текст при отсеве |
| `earlyFinishMessage` | стандартный | Текст при досрочном завершении |
| `closedMessage` | «Опрос закрыт.» | Текст, когда сбор закрыт, срок вышел или набран лимит |
| `overquotaMessage` | стандартный | Текст, когда респондент попал в набранную квоту |
| `redirectComplete`, `redirectScreenout`, `redirectEarlyFinish`, `redirectOverquota` | — | Адрес перехода после завершения / отсева / досрочного выхода вместо сообщения. Подстановки кодируются для URL: `{{param.pid}}`, `{{Q1}}` (код ответа), `{{resp_id}}` |
| `password` | — | Пароль на опрос (в браузер респондента не передаётся) |
| `openFrom`, `closeAt` | — | Начало и окончание сбора, ISO 8601: `"2026-10-01T09:00:00+03:00"` |
| `maxResponses` | — | Закрыть сбор после N завершённых анкет |
| `allowRetake` | `false` | Разрешить пройти опрос ещё раз с того же устройства |
| `uniqueParam` | — | Один ответ на значение параметра ссылки (например, `"pid"` для панели): начатую анкету можно продолжить с любого устройства, повторно пройти нельзя; без параметра опрос не открывается |
| `maxStartsPerIpHour` | — | Не больше N новых анкет с одного IP за час |
| `minDurationSec` | — | Завершённые быстрее N секунд помечаются как «спидеры» (переменная `speeder` в выгрузке) |
| `logoUrl` | — | Логотип над опросом (https://…) |
| `accentColor` | — | Основной цвет, `#RRGGBB` |
| `footerText` | — | Текст внизу страницы (форматирование и ссылки) |
| `nextLabel`, `backLabel`, `submitLabel`, `earlyFinishLabel` | «Далее», «Назад», «Отправить», «Завершить опрос досрочно» | Надписи на кнопках |

Встраивание на сайт: код iframe — в «Настройках» анкеты; высота подстраивается под содержимое автоматически.

Тестовая ссылка на черновик без входа в админку: `/s/<id>?test=<ключ>` (ключ — в «Настройках» анкеты).

## Общие поля вопроса

| Поле | Описание |
|---|---|
| `id`, `type`, `text` | Обязательны. `text` — текст вопроса, переносы `\n` сохраняются. Форматирование: `**жирный**`, `*курсив*`, `[ссылка](https://…)`, `![картинка](https://…)` |
| `hint` | Подсказка под вопросом |
| `required` | По умолчанию `true`. `false` — можно пропустить |
| `showIf` | Условие показа (см. «Условия») |
| `actions` | Действия: `{ "before": [...], "after": [...] }` (см. «Действия») |
| `hideBack`, `hideFinish` | Скрыть кнопку «Назад» / «Завершить» на этом вопросе |
| `requiredMessage` | Своё сообщение, если на обязательный вопрос не ответили |
| `note` | Комментарий для команды — респондент его не видит |
| `fixed` | В блоке с `order` — оставить вопрос на своём месте |
| `prefillParam` | Предзаполнить ответ из параметра ссылки: `?age=35` → `"prefillParam": "age"`. Для вариантов — код, для multi — коды через запятую; неподходящее значение игнорируется |
| `prefillSkip` | С `prefillParam`: если ответ пришёл из ссылки — не показывать вопрос (ответ записывается) |
| `scripts` | JS-скрипты (см. «Скрипты») |

## Типы вопросов

### single — один ответ
```json
{ "id": "Q1", "type": "single", "text": "Ваш пол", "options": [
  { "code": 1, "text": "Мужской" },
  { "code": 2, "text": "Женский" }
] }
```
- `options[].other: true` — вариант с полем «укажите» (текст обязателен при выборе).
- `options[].fixed: true` — вариант остаётся на своём месте при перемешивании и ротации.
- `options[].hidden: true` — вариант не показывается респонденту, но его код остаётся в выгрузке (так «выключают» вариант, не ломая данные). Работает и для строк матрицы.
- `columnCount`: 2 или 3 — варианты в колонки (на телефоне всегда одна).
- `order`: `"random"` — перемешать, `"rotate"` — ротация (циклический сдвиг). «Другое» и эксклюзивные варианты остаются внизу.
- `showOtherAlways: true` — поле «укажите» видно сразу; ввод текста отмечает вариант.
- `autoNext: true` — переход дальше сразу после выбора (кроме «Другое»).
- `optionsFrom` — перенос вариантов (см. ниже).

### multi — несколько ответов
Как `single` (без `autoNext`), плюс:
- `options[].exclusive: true` — вариант снимает все остальные («Ничего из перечисленного»).
- `minSelected`, `maxSelected` — сколько можно выбрать.

### dropdown — выпадающий список
Как `single`. Для длинных списков.

### ranking — ранжирование
```json
{ "id": "Q7", "type": "ranking", "text": "Расставьте по важности", "rankCount": 3, "options": [
  { "code": 1, "text": "Цена" }, { "code": 2, "text": "Вкус" }, { "code": 3, "text": "Сервис" }, { "code": 4, "text": "Интерьер" }
] }
```
- Респондент нажимает на варианты по порядку (1 — самое важное), порядок можно менять стрелками.
- `rankCount` — сколько мест заполнить (по умолчанию все варианты). `order`, `optionsFrom` — как у single.
- Ответ — массив кодов по порядку мест. В выгрузке `Q7_<код>` = место варианта (пусто — не попал в топ).
- В условиях работает как multi: `contains` — вариант попал в ранжирование.

### text — открытый ответ
- `multiline: true` — большое поле, `rows` — его высота в строках (2–20, по умолчанию 4); `minLength`, `maxLength` — длина ответа.
- `pattern` — регулярное выражение, которому должен соответствовать весь ответ (например, `"[А-Яа-яЁё\\s-]+"` — в JSON обратный слеш удваивается); `patternMessage` — текст ошибки.
- `placeholder` — подсказка внутри поля.
- `inputType`: `"email"` — проверка e-mail, `"time"` — время ЧЧ:ММ.
- `noPaste: true` — запретить вставку из буфера обмена.

### number — число
- `min`, `max`; `decimals` — знаков после запятой (по умолчанию 0, только целые).
- `suffix` — единица измерения справа от поля («лет», «₽»); `placeholder` — подсказка внутри поля.

### scale — шкала / NPS
```json
{ "id": "NPS", "type": "scale", "text": "Порекомендуете ли вы нас?", "from": 0, "to": 10,
  "labels": { "0": "Точно нет", "10": "Точно да" },
  "extraOptions": [{ "code": 99, "text": "Затрудняюсь ответить" }] }
```
- До 21 точки. `labels` — подписи точек. Коды `extraOptions` не должны попадать в диапазон. `autoNext` — как у single.

### matrix — матрица
```json
{ "id": "Q5", "type": "matrix", "mode": "single", "text": "Оцените по параметрам",
  "rows": [
    { "code": 1, "text": "Цена" },
    { "code": 2, "text": "Качество" },
    { "code": 9, "text": "Другое", "other": true }
  ],
  "columns": [
    { "code": 1, "text": "Плохо" }, { "code": 2, "text": "Нормально" }, { "code": 3, "text": "Хорошо" }
  ] }
```
- `mode`: `single` — один ответ в строке, `multi` — несколько.
- `requiredRows`: `"all"` (по умолчанию), `"none"` или число N — минимум заполненных строк.
- Строка с `other: true` — респондент вписывает свою формулировку; необязательна, но текст и оценка идут вместе.
- `rowOrder`: `"random"` / `"rotate"`. `rowsFrom` — перенос строк.
- Отображение: `transpose` (перевернуть таблицу), `verticalHeaders` (вертикальные заголовки столбцов), `progressiveRows` (строки по мере ответа), `carousel` (по одной строке).
- На телефоне матрица показывается карточками.

### date — дата
Значение `YYYY-MM-DD`. `min`, `max` — в том же формате.

### phone — телефон
`format`: `"ru"` (по умолчанию, +7 и 10 цифр, маска) или `"international"`. Сохраняется как `+79161234567`.

### info — информационный экран
Только текст, без ответа.

### hidden — скрытая переменная
```json
{ "id": "H_panel", "type": "hidden", "text": "ID панелиста", "fromParam": "pid", "valueType": "string" }
```
Не показывается. Значение — из параметра ссылки (`fromParam`), действия `setValue`, скрипта `sl.set(...)` или **формулы** `calc`. `valueType`: `"string"` / `"number"`. Доступна в условиях, квотах и подстановках.

**Вычисляемые переменные.** `"calc": "score(Q1) + score(Q2)"` — значение пересчитывается после каждого ответа (число).
- Ответ на вопрос — его ID: `Q5` (число, код варианта; нет ответа — 0). Операторы `+ - * /`, скобки, сравнения `> < >= <= == !=` (дают 1 или 0).
- Функции: `score(Q)` — сумма баллов выбранных вариантов (`options[].score`; для матрицы — баллы столбцов `columns[].score`; для шкалы — значение точки),
  `count(Q)` — сколько выбрано, `answered(Q)` — 1/0, `sum`, `avg`, `min`, `max`, `round(x, знаков)`, `if(условие, да, нет)`.
- Пример индекса: `{ "id": "H_idx", "type": "hidden", "text": "Индекс лояльности", "calc": "round(avg(Q1, Q2, Q3), 1)" }`, сегмент: `"calc": "if(H_idx >= 4, 1, 2)"`.

## Условия

Используются в `showIf` и в поле `if` у действий.
```json
{ "q": "Q1", "op": "eq", "value": 2 }
{ "all": [ { "q": "S1", "op": "gte", "value": 18 }, { "q": "Q2", "op": "contains", "value": 3 } ] }
{ "any": [ ... ] }
{ "not": { "q": "Q3", "op": "answered" } }
```

| Поле | Описание |
|---|---|
| `q` | ID вопроса |
| `row` | Код строки — **обязательно для матриц** (кроме `answered`/`notAnswered`) |
| `param` | Вместо `q`: параметр ссылки, `?src=vk` → `{ "param": "src", "op": "eq", "value": "vk" }` |
| `op` | Оператор |
| `value` | Значение (для `in`, `notIn`, `containsAny`, `containsAll` — массив) |

| Оператор | Смысл |
|---|---|
| `eq`, `neq` | равно / не равно (для multi: выбран / не выбран код) |
| `gt`, `gte`, `lt`, `lte` | больше, ≥, меньше, ≤ (числа, коды, даты `YYYY-MM-DD`) |
| `in`, `notIn` | значение из списка / не из списка |
| `contains`, `notContains` | multi: выбран / не выбран код |
| `containsAny`, `containsAll` | multi: выбран любой / все из списка |
| `answered`, `notAnswered` | есть ответ / нет ответа |

Если на вопрос нет ответа, все операторы кроме `notAnswered` дают `false`.
Вопрос, для которого не осталось видимых вариантов, пропускается автоматически.

## Действия

Логика без программирования, как в Survey Studio. У вопроса два списка: `before` (перед показом) и `after` (после ответа).
Действия выполняются по порядку; у каждого может быть условие `if` (без условия — выполняется всегда).

```json
"actions": {
  "before": [
    { "do": "hideOptionsFrom", "question": "Q1", "filter": "notSelected" },
    { "do": "answer" }
  ],
  "after": [
    { "if": { "q": "S1", "op": "lt", "value": 18 }, "do": "screenout" },
    { "if": { "q": "Q4", "op": "gte", "value": 7 }, "do": "goTo", "target": "B_profile" }
  ]
}
```

**Перед показом (`before`):**

| `do` | Параметры | Что делает |
|---|---|---|
| `hideOptions` | `codes` | Скрыть варианты (строки матрицы) с этими кодами |
| `showOnlyOptions` | `codes` | Оставить только эти варианты |
| `hideOptionsFrom` | `question`, `filter` | Скрыть варианты, выбранные (`selected`, по умолчанию) или не выбранные (`notSelected`) в другом вопросе |
| `skipIfFewer` | `n` | Не показывать вопрос, если видимых вариантов меньше `n` |
| `answer` | `value` (необязательно) | Отметить ответ и не показывать вопрос. Без `value` — единственный оставшийся вариант (если он один) |
| `setValue` | `target`, `value` | Записать значение в скрытую переменную. В `value` можно `{{Q1}}` |

**После ответа (`after`):**

| `do` | Параметры | Что делает |
|---|---|---|
| `goTo` | `target` | Перейти к вопросу или к блоку (ID вопроса / блока). Только вперёд |
| `end` | `message`, `redirect` (необязательно) | Завершить анкету (статус «Завершён»). Своё сообщение или адрес перехода для этой ветки вместо общих из настроек |
| `screenout` | `message`, `redirect` (необязательно) | Отсеять респондента; `message` / `redirect` — как у `end` (например, разные причины отсева) |
| `setValue` | `target`, `value` | Записать значение в скрытую переменную |
| `error` | `message` | Не пускать дальше и показать сообщение (обычно с условием) |

Первое сработавшее `goTo` / `end` / `screenout` определяет, куда идти. Если ни одно не сработало — следующий вопрос.

### Подстановка (пайпинг)
В `text` и `hint`: `{{Q2}}` — текст ответа (для multi — через запятую; «Другое» — вписанный текст); `{{Q5.2}}` — ответ в строке 2 матрицы Q5; `{{param.city}}` — параметр ссылки.

### Перенос вариантов — `optionsFrom` / `rowsFrom`
```json
{ "id": "Q2", "type": "single", "text": "Какой из них главный?",
  "optionsFrom": { "question": "Q1", "filter": "selected" }, "options": [] }
```
- `filter`: `selected` / `notSelected` / `all`. Коды сохраняются, «Другое» переносится с текстом респондента, эксклюзивные варианты — нет.
- В `options` можно добавить свои варианты (например, 99 «Ни один») — они будут в конце.
- Источник — `single`, `multi`, `dropdown` или `matrix` (строки с ответом).

## Квоты

```json
"quotas": [
  { "id": "QT_m", "title": "Мужчины", "if": { "q": "S2", "op": "eq", "value": 1 }, "limit": 150 },
  { "id": "QT_msk", "title": "Москва из VK", "if": { "all": [ { "q": "S3", "op": "eq", "value": 1 }, { "param": "src", "op": "eq", "value": "vk" } ] }, "limit": 50 }
]
```
- Считаются **завершённые** анкеты, чьи ответы подходят под условие `if` (условие — как в `showIf`, можно по параметрам ссылки).
- После каждого ответа (и сразу при старте — для условий по параметрам ссылки) респондент, подходящий под набранную квоту, завершает опрос со статусом «Сверх квоты» (`status` = 4), видит `overquotaMessage` или уходит на `redirectOverquota`. Отсев (`screenout`) важнее квоты.
- `limit: 0` — ячейка закрыта сразу. Квотные вопросы ставьте в начало анкеты (скринер).
- Тестовые ответы считаются отдельно от настоящих.

## CSS
Поле `css` — стили страницы опроса. Классы: `.runner`, `.runner-card`, `.page-<ID вопроса>`, `.question`, `#q-<ID вопроса>`,
`.option`, `.option.selected`, `.matrix`, `.scale-point`, `.btn-primary`, `.progress-fill`. Цвет акцента: `:root { --accent: #e4002b; }`.

## Скрипты
Для случаев, которые не покрываются действиями. Скрипт — тело JavaScript-функции с объектом `sl`, выполняется **в браузере респондента**.
Сервер скрипты не выполняет и всегда сам проверяет ответы.

| Где | Хук | Когда | Возвращает |
|---|---|---|---|
| анкета `scripts` | `init` | На каждом экране, до остальных | — |
| вопрос `scripts` | `onShow` | При показе вопроса | — |
| вопрос `scripts` | `onChange` | При изменении ответа | — |
| вопрос `scripts` | `validate` | Перед «Далее», после встроенных проверок и действий | строка — ошибка |

`sl.get(id)`, `sl.text(id)`, `sl.set(id, value)`, `sl.value`, `sl.question`, `sl.params`, `sl.respondentId`, `sl.preview`, `sl.el` (DOM-элемент вопроса), `sl.shared` (общий объект для функций из `init`).

## Выгрузка

| Тип | Переменные в Excel/SPSS |
|---|---|
| single, dropdown | `Q1` (код, с метками значений) + `Q1_97_other` |
| multi | `Q1_1`, `Q1_2`, … (0/1) + `Q1_97_other` |
| ranking | `Q7_1`, `Q7_2`, … (место варианта) |
| matrix single | `Q5_1`, `Q5_2`, … (код столбца по строке) + `Q5_9_other` |
| matrix multi | `Q5_<строка>_<столбец>` (0/1) |
| scale, number | `Q1` (число) |
| text, phone | `Q1` (строка) |
| date | `Q1` (дата) |
| hidden | `H1` (строка или число) |

Служебные: `resp_id`, `status` (1 завершён, 2 отсеян, 3 досрочно, 4 сверх квоты, 0 не завершён), `started_at`, `completed_at`, `duration_sec`, `speeder` (если задан `minDurationSec`), `ip`,
`user_agent`, `version`, `url_<параметр>` для каждого параметра ссылки; `rejected` (если в выгрузку включён брак);
`t_<ID вопроса>` — секунды на вопросе (если при выгрузке отмечено «Время на каждом вопросе»). Форматы: Excel, SPSS, CSV (разделитель `;`), Google Sheets.

## Правила для генерации анкеты с помощью ИИ

1. Возвращай только JSON, без комментариев и Markdown. `formatVersion` всегда `2`.
2. ID вопросов сохраняй из исходной анкеты (S1, Q1, Q1a…); если их нет — `Q1`, `Q2`, …; скринер — `S1`…; демография — `D1`…
3. Разделы исходной анкеты — блоки (`B1`, `B2`… или осмысленные `B_screen`, `B_main`), с `title`, если у раздела есть название.
4. «ОДИН ОТВЕТ» → `single`; «НЕСКОЛЬКО ОТВЕТОВ» → `multi`; «ЗАПИСАТЬ» → `text`; таблица оценок → `matrix`; «0–10» → `scale`; «ПРОРАНЖИРУЙТЕ» → `ranking`.
5. «Другое (укажите)» → `"other": true`; «Ничего / Затрудняюсь» в multi → `"exclusive": true`. Коды: «Другое» 97, «Затрудняюсь» 99, если не указано иное.
6. «ЕСЛИ В Q1 КОД 2 → ЗАДАТЬ Q3» → `showIf` у Q3.
7. Квоты из ТЗ («КВОТА: мужчины — 150») → `quotas`.
8. «ЕСЛИ МЛАДШЕ 18 → ЗАВЕРШИТЬ / СКРИНАУТ» → действие `after` у этого вопроса: `{ "if": ..., "do": "screenout" }`.
9. «ПЕРЕЙТИ К Q10» → действие `after`: `{ "if": ..., "do": "goTo", "target": "Q10" }`.
10. «ЗАДАТЬ ПО ВЫБРАННЫМ В Q1» → `optionsFrom` / `rowsFrom` с `"filter": "selected"`. «НЕ ПОКАЗЫВАТЬ ВЫБРАННЫЕ В Q1» → действие `before` `hideOptionsFrom`.
11. «РОТАЦИЯ» → `"order": "rotate"`; «СЛУЧАЙНЫЙ ПОРЯДОК» → `"order": "random"` (для строк матрицы — `rowOrder`). «ВОПРОСЫ БЛОКА В СЛУЧАЙНОМ ПОРЯДКЕ» → `"order"` у блока.
12. Условия ссылаются только на вопросы, которые идут раньше.
