# Формат анкеты SurveyLAB (formatVersion 1)

Анкета — один JSON-объект. Полный рабочий пример: `examples/demo.json`.

## Структура

```json
{
  "formatVersion": 1,
  "title": "Название, которое видит респондент",
  "description": "Для команды (необязательно)",
  "settings": { "showProgress": true, "allowBack": true, "allowEarlyFinish": false },
  "css": "",
  "scripts": { "init": "" },
  "pages": [
    { "id": "P1", "title": "Необязательный заголовок", "questions": [ ... ], "jumps": [ ... ] }
  ]
}
```

- Анкета состоит из **страниц** (`pages`), на странице — **вопросы** (`questions`). Респондент видит одну страницу за раз.
- `id` страниц и вопросов: латиница, цифры и `_`, начинается с буквы, до 32 символов, уникальны (без учёта регистра).
  ID вопроса = имя переменной в выгрузке (Excel/SPSS), поэтому используйте короткие ID вроде `S1`, `Q5`, `D2`.
- Зарезервированы: `resp_id`, `status`, `started_at`, `completed_at`, `duration_sec`, `ip`, `user_agent`, `is_test`, `version`.
- **Коды** вариантов — целые числа, уникальные внутри списка. Принято: 97 — «Другое», 98 — «Отказ», 99 — «Затрудняюсь ответить».

### settings

| Поле | По умолчанию | Что делает |
|---|---|---|
| `showProgress` | `true` | Полоса прогресса |
| `allowBack` | `true` | Кнопка «Назад» |
| `allowEarlyFinish` | `false` | Кнопка «Завершить опрос досрочно» (статус «Завершён досрочно») |
| `completeMessage` | «Спасибо! Ваши ответы сохранены.» | Текст после завершения |
| `screenoutMessage` | стандартный | Текст при отсеве |
| `earlyFinishMessage` | стандартный | Текст при досрочном завершении |
| `closedMessage` | «Опрос закрыт.» | Текст, когда сбор закрыт |

## Общие поля вопроса

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Имя переменной |
| `type` | да | Тип (см. ниже) |
| `text` | да | Текст вопроса. Переносы строк `\n` сохраняются |
| `hint` | нет | Подсказка под вопросом |
| `required` | нет | По умолчанию `true`. `false` — можно пропустить |
| `showIf` | нет | Условие показа (см. «Логика») |
| `scripts` | нет | Скрипты вопроса (см. «Скрипты») |

## Типы вопросов

### single — один ответ (радиокнопки)
```json
{ "id": "Q1", "type": "single", "text": "Ваш пол", "options": [
  { "code": 1, "text": "Мужской" },
  { "code": 2, "text": "Женский" }
] }
```
- `options[].other: true` — вариант с полем «укажите» (текст обязателен при выборе).
- `randomize: true` — перемешать варианты (варианты с `other` и `exclusive` остаются внизу).
- `optionsFrom` — перенос вариантов (см. ниже).

### multi — несколько ответов (чекбоксы)
Как `single`, плюс:
- `options[].exclusive: true` — вариант снимает все остальные («Ничего из перечисленного»).
- `minSelected`, `maxSelected` — ограничения количества.

### dropdown — выпадающий список
Как `single`. Удобно для длинных списков (города, бренды).

### text — открытый ответ
- `multiline: true` — большое поле; `maxLength` — лимит символов.

### number — число
- `min`, `max`; `decimals` — знаков после запятой (по умолчанию 0 — только целые).

### scale — шкала / NPS
```json
{ "id": "NPS", "type": "scale", "text": "Порекомендуете ли вы нас?", "from": 0, "to": 10,
  "labels": { "0": "Точно нет", "10": "Точно да" },
  "extraOptions": [{ "code": 99, "text": "Затрудняюсь ответить" }] }
```
- До 21 точки. `labels` — подписи точек (обычно крайних). Коды `extraOptions` не должны попадать в диапазон шкалы.

### matrix — матрица
```json
{ "id": "Q5", "type": "matrix", "mode": "single", "text": "Оцените по параметрам",
  "requiredRows": "all",
  "rows": [
    { "code": 1, "text": "Цена" },
    { "code": 2, "text": "Качество" },
    { "code": 9, "text": "Другое", "other": true }
  ],
  "columns": [
    { "code": 1, "text": "Плохо" }, { "code": 2, "text": "Нормально" }, { "code": 3, "text": "Хорошо" }
  ] }
```
- `mode`: `single` — один ответ в строке, `multi` — несколько.
- `requiredRows`: `"all"` (по умолчанию) — все строки обязательны; `"none"` — необязательны; число N — минимум N строк.
- Строка с `other: true` — респондент вписывает свою формулировку. Она необязательна, но если вписан текст — нужна оценка, и наоборот.
- `randomizeRows: true` — перемешать строки. `rowsFrom` — перенос строк из другого вопроса.
- На телефоне матрица автоматически показывается карточками.

### date — дата
- Значение `YYYY-MM-DD`. `min`, `max` — в том же формате.

### phone — телефон
- `format`: `"ru"` (по умолчанию, +7 и 10 цифр, маска ввода) или `"international"` (+ и 8–15 цифр).
- Сохраняется нормализованным: `+79161234567`.

### info — информационный блок
Только текст, без ответа.

### hidden — скрытая переменная
```json
{ "id": "H_panel", "type": "hidden", "text": "ID панелиста", "fromParam": "pid", "valueType": "string" }
```
- Не показывается. Значение приходит из параметра ссылки (`fromParam`) или задаётся скриптом `sl.set("H_panel", ...)`.
- `valueType`: `"string"` или `"number"` — тип переменной в выгрузке.
- Доступна в условиях и подстановках как обычный вопрос. Аналог «скрипта подготовки»: группы квот, ячейки теста, вычисленные индексы.

## Логика

### Условие показа вопроса или страницы — `showIf`
```json
"showIf": { "q": "Q1", "op": "eq", "value": 2 }
```
Составные условия:
```json
"showIf": { "all": [ { "q": "S1", "op": "gte", "value": 18 }, { "q": "Q2", "op": "contains", "value": 3 } ] }
"showIf": { "any": [ ... ] }
"showIf": { "not": { "q": "Q3", "op": "answered" } }
```
Вложенность любая. Страница, на которой не осталось видимых вопросов, пропускается автоматически.

| Поле | Описание |
|---|---|
| `q` | ID вопроса |
| `row` | Код строки — **обязательно для матриц** (кроме `answered`/`notAnswered`) |
| `param` | Вместо `q`: параметр ссылки, например `?src=vk` → `{ "param": "src", "op": "eq", "value": "vk" }` |
| `op` | Оператор |
| `value` | Значение (для `in`, `notIn`, `containsAny`, `containsAll` — массив) |

| Оператор | Смысл |
|---|---|
| `eq`, `neq` | равно / не равно (для multi: выбран / не выбран код) |
| `gt`, `gte`, `lt`, `lte` | больше, ≥, меньше, ≤ (числа, коды шкал, даты `YYYY-MM-DD`) |
| `in`, `notIn` | значение из списка / не из списка |
| `contains`, `notContains` | multi: выбран / не выбран код |
| `containsAny`, `containsAll` | multi: выбран любой / все из списка |
| `answered`, `notAnswered` | есть ответ / нет ответа |

Если на вопрос нет ответа, все операторы кроме `notAnswered` дают `false`.

### Переходы — `jumps` (на странице)
```json
"jumps": [
  { "if": { "q": "S1", "op": "lt", "value": 18 }, "goTo": "SCREENOUT" },
  { "if": { "q": "S2", "op": "eq", "value": 1 }, "goTo": "P5" }
]
```
- Проверяются после отправки страницы, по порядку; срабатывает первое подходящее правило. Если ни одно не подошло — следующая страница.
- `goTo`: ID страницы (только вперёд), `END` — завершить опрос, `SCREENOUT` — отсеять респондента.
- Для одиночного отсеивающего вопроса удобнее переход, для показа/скрытия блоков — `showIf`.

### Подстановка (пайпинг)
В `text`, `hint` и заголовках страниц:
- `{{Q2}}` — текст ответа на вопрос (для multi — через запятую; «Другое» — вписанный текст);
- `{{Q5.2}}` — ответ в строке 2 матрицы Q5;
- `{{param.city}}` — параметр ссылки `?city=...`.

### Перенос вариантов — `optionsFrom` / `rowsFrom`
```json
{ "id": "Q2", "type": "single", "text": "Какой из них главный?",
  "optionsFrom": { "question": "Q1", "filter": "selected" }, "options": [] }
```
- `filter`: `selected` — выбранные в исходном вопросе, `notSelected` — невыбранные, `all` — все.
- Коды сохраняются. «Другое» переносится с текстом респондента. Эксклюзивные варианты не переносятся.
- В `options` можно добавить собственные варианты (например, 99 «Ни один») — они будут в конце.
- Если переносить нечего, вопрос скрывается.
- Источник — `single`, `multi`, `dropdown` или `matrix` (переносятся строки с ответом).

## CSS
Поле `css` — стили страницы опроса. Классы: `.runner`, `.runner-card`, `.page-<ID страницы>`, `.question`, `#q-<ID вопроса>`,
`.option`, `.option.selected`, `.matrix`, `.scale-point`, `.btn-primary`, `.progress-fill`. Цвет акцента: `:root { --accent: #e4002b; }`.

## Скрипты

Скрипт — тело JavaScript-функции, получающей объект `sl`. Выполняется **в браузере респондента**.
Сервер скрипты не выполняет и всегда сам проверяет ответы, поэтому скрипт не может «сломать» данные — но может добавить свою проверку, задать скрытую переменную или изменить внешний вид.

| Где | Хук | Когда | Возвращаемое значение |
|---|---|---|---|
| анкета `scripts` | `init` | При показе каждой страницы, до остальных | — |
| страница `scripts` | `onShow` | При показе страницы | — |
| страница `scripts` | `onSubmit` | Перед отправкой страницы | строка — ошибка, отправка отменяется |
| вопрос `scripts` | `onShow` | Когда вопрос появился на экране | — |
| вопрос `scripts` | `onChange` | При каждом изменении ответа | — |
| вопрос `scripts` | `validate` | Перед «Далее», после встроенных проверок | строка — ошибка у вопроса |

Объект `sl`:

| Свойство | Описание |
|---|---|
| `sl.get(id)` | Значение ответа: код, массив кодов, строка, число, объект матрицы `{ "код строки": код столбца }` |
| `sl.text(id)` | Текст ответа, как в подстановке |
| `sl.set(id, value)` | Задать значение скрытой переменной (или ответа на вопрос текущей страницы) |
| `sl.value` | Текущее значение (в `onChange`, `validate`, `onShow` вопроса) |
| `sl.question`, `sl.page` | ID текущего вопроса и страницы |
| `sl.params` | Параметры ссылки |
| `sl.respondentId` | ID сессии респондента |
| `sl.preview` | `true` в предпросмотре |
| `sl.el` | DOM-элемент вопроса (или карточки страницы) |
| `sl.shared` | Общий объект: `init` может положить сюда функции для других скриптов |

Примеры:
```json
"scripts": { "validate": "if (sl.value > sl.get('S1')) return 'Стаж не может быть больше возраста';" }
```
```json
"scripts": { "onShow": "sl.set('H_cell', Math.random() < 0.5 ? 'A' : 'B');" }
```
Ошибки в скриптах не останавливают опрос (в предпросмотре показываются во всплывающем окне).

## Ответы и выгрузка

| Тип | Переменные в Excel/SPSS |
|---|---|
| single, dropdown | `Q1` (код, с метками значений) + `Q1_97_other` (текст «Другое») |
| multi | `Q1_1`, `Q1_2`, … (0/1) + `Q1_97_other` |
| matrix single | `Q5_1`, `Q5_2`, … (код столбца по строке) + `Q5_9_other` |
| matrix multi | `Q5_<строка>_<столбец>` (0/1) |
| scale, number | `Q1` (число) |
| text, phone | `Q1` (строка) |
| date | `Q1` (дата) |
| hidden | `H1` (строка или число) |

Служебные переменные: `resp_id`, `status` (1 завершён, 2 отсеян, 3 досрочно, 0 не завершён), `started_at`, `completed_at`,
`duration_sec`, `ip`, `user_agent`, `version`, а также `url_<параметр>` для каждого параметра ссылки.

## Правила для генерации анкеты с помощью ИИ

1. Возвращай только JSON, без комментариев и без Markdown.
2. `formatVersion` всегда `1`.
3. ID вопросов сохраняй из исходной анкеты (S1, Q1, Q1a…); если их нет — нумеруй `Q1`, `Q2`, …; скринер — `S1`, `S2`; демография — `D1`, `D2`.
4. Каждый блок/экран исходной анкеты — отдельная страница; несвязанные короткие вопросы можно объединять на одной странице.
5. Инструкции вида «ОДИН ОТВЕТ» → `single`; «НЕСКОЛЬКО ОТВЕТОВ» → `multi`; «ЗАПИСАТЬ» → `text`; таблицы оценок → `matrix`; «0–10» → `scale`.
6. «Другое (укажите)» → `"other": true`; «Ничего / Затрудняюсь» в multi → `"exclusive": true`. Коды «Другое» — 97, «Затрудняюсь» — 99, если в анкете не указано иное.
7. «ЕСЛИ В Q1 КОД 2 → ЗАДАТЬ Q3» → `showIf` у Q3. «ЕСЛИ МЛАДШЕ 18 → ЗАВЕРШИТЬ» → переход `SCREENOUT` на странице с вопросом. «ПЕРЕЙТИ К Q10» → переход на страницу с Q10.
8. «ЗАДАТЬ ПО ВЫБРАННЫМ В Q1» → `optionsFrom` / `rowsFrom` с `"filter": "selected"`.
9. «РОТАЦИЯ» → `randomize` / `randomizeRows`.
10. Условия ссылаются только на вопросы, которые идут раньше.
