# SurveyLAB

Сервис опросов для команды: конструктор анкет, импорт анкеты из JSON (в том числе сгенерированного ИИ), прохождение с телефона, выгрузка в Excel, SPSS (.sav) и Google Sheets.

## Возможности

- **Типы вопросов:** один ответ, несколько ответов, выпадающий список, ранжирование, открытый текст, число, шкала / NPS, матрица (один или несколько ответов в строке, обязательность всех строк / N строк / необязательно), дата, телефон, информационный блок, скрытая переменная.
- **«Другое (укажите)»** в любых вариантах и в строках матрицы; эксклюзивные варианты («Ничего из перечисленного»).
- **Один вопрос на экран**, вопросы сгруппированы в блоки. Вся логика — на уровне вопроса.
- **Логика без кода (действия, как в Survey Studio):** условие показа (И / ИЛИ / НЕ); перед показом — скрыть / оставить варианты, скрыть варианты по другому вопросу, пропустить при малом числе вариантов, отметить ответ без показа, записать переменную; после ответа — перейти к вопросу или блоку, завершить, отсеять, записать переменную, показать ошибку.
- **Настройки вопроса** (свёрнуты в окне вопроса): рандомизация / ротация, закрепление и скрытие отдельных вариантов, варианты в колонки, скрыть «Назад» / «Завершить», перевёрнутая таблица, вертикальные заголовки, строки по мере ответа, карусель, дробные числа и единица измерения, e-mail / время, длина ответа и проверка формата, подсказка в поле, своё сообщение об обязательности, запрет вставки, автопереход, поле «Другое» всегда видно, комментарий для команды.
- **Блоки:** вопросы блока можно показывать в случайном порядке или с ротацией (свой порядок у каждого респондента, отдельные вопросы можно закрепить).
- **Настройки анкеты:** сроки сбора, лимит завершённых анкет, пароль, повторное прохождение, тестовая ссылка без входа, логотип, цвет, подвал, надписи на кнопках, номера вопросов, сообщения и **редиректы** после завершения / отсева / квоты / досрочного выхода (для панелей: `?pid={{param.pid}}`).
- **Квоты:** условие по ответам и параметрам ссылки + лимит; сверх лимита — статус «Сверх квоты» со своим сообщением или редиректом; прогресс в админке.
- **Защита:** один ответ на ID панелиста (`uniqueParam`), лимит анкет с одного IP, пометка «спидеров», ограничение попыток входа в админку.
- **Пайпинг** `{{Q1}}`, **перенос вариантов** из предыдущих вопросов, **предзаполнение** ответов из параметров ссылки.
- **Вычисления:** баллы вариантов и вычисляемые переменные по формулам (`score(Q1) + score(Q2)`, `if(...)`, `avg(...)`) — индексы и сегменты прямо в анкете.
- **Встраивание на сайт:** код iframe с автоматической подстройкой высоты.
- **Для респондента:** шкала числами, звёздами или смайликами, картинки у вариантов, ограничение времени с таймером.
- **Шаблоны:** NPS, CSAT, вовлечённость сотрудников, оценка мероприятия, демо — при создании анкеты.
- **Отладка в предпросмотре:** панель со всеми ответами, переменными, результатами формул и параметрами ссылки.
- **Скрипты и CSS** — для того, что не покрывают действия: глобальный скрипт, `onShow` / `onChange` / `validate` у вопроса, свой CSS.
- **Интерфейс респондента:** мобильная вёрстка, прогресс, «Назад», «Завершить досрочно» (отключаются в настройках), Enter — «Далее», продолжение с места остановки после перезагрузки.
- **Конструктор:** лента карточек в том виде, как их увидит респондент; клик по карточке открывает окно вопроса (варианты / строки и столбцы по типу, предпросмотр, свёрнутые «Действия» и «Настройки»); «+» между карточками, перетаскивание, быстрый ввод вариантов (Enter, вставка списка).
- **JSON ⇄ конструктор** синхронизируются в обе стороны. Кнопка «Скопировать инструкцию для ИИ» копирует документацию формата вместе с заданием.
- **Черновик сохраняется автоматически**, есть отмена и повтор (Ctrl+Z / Ctrl+Shift+Z, Ctrl+S — сохранить сразу); респонденты видят изменения только после публикации.
- **Безопасное переименование:** смена ID вопроса обновляет все ссылки — условия, действия, подстановки, перенос вариантов, скрипты.
- **Удобство в больших анкетах:** поиск по вопросам, сворачивание блоков, копирование вопросов между анкетами (JSON через буфер обмена), перенумерация кодов.
- **Карта логики** (вкладка «Логика»): все переходы линиями, откуда и куда ведёт каждый вопрос, условия показа и точки отсева; поиск недостижимых вопросов и путей без завершения; длина анкеты — минимум и максимум вопросов и примерное время.
- **Тестирование:** предпросмотр с любого вопроса; тестовое заполнение — боты проходят анкету по логике со случайными ответами (проверка маршрутов и выгрузки); тестовые ответы не попадают в обычные выгрузки.
- **Форматирование текста:** жирный, курсив, ссылки и картинки в вопросах, подсказках и сообщениях.
- **Отчёт:** распределения ответов по каждому вопросу, NPS, средние, матрицы тепловой картой, ответы «Другое», где бросают анкету; отчёт по подгруппе (условие по ответам или параметрам ссылки).
- **Уведомления:** вебхук (JSON с ответами) и Telegram — о каждой или каждой N-й завершённой анкете, набранной квоте и лимите.
- **Работа с анкетами:** выделение нескольких вопросов и массовые действия, архив, история опубликованных версий с возвратом в черновик, печатная версия анкеты для согласования.
- **Команда:** главный администратор из `.env` добавляет коллег (меню с логином → «Пользователи») с ролями: администратор (всё, включая пользователей и резервные копии), редактор (анкеты и данные), наблюдатель (только просмотр, отчёты и выгрузки). Пароли хранятся в виде хеша (scrypt); у версий анкеты видно, кто опубликовал.
- **Данные:** просмотр и удаление отдельных ответов; SQLite, метаданные (время начала и окончания, длительность, IP, User-Agent, параметры ссылки/UTM, статус), выгрузка в Excel (коды, метки, кодбук), SPSS .sav (метки переменных и значений, типы шкал), автоматическая запись в Google Sheets.

Формат анкеты: [docs/survey-format.md](docs/survey-format.md). Пример: [examples/demo.json](examples/demo.json).

## Запуск локально

Нужен Node.js 22.5+ (рекомендуется 24).

```bash
npm install
cp .env.example .env      # укажите ADMIN_PASSWORD
npm run dev               # сервер :3000 + фронтенд :5173 с автоперезагрузкой
```

Админка: http://localhost:5173/admin, опрос: `/s/<id>`.

Тесты: `npm test` (тест .sav использует Python + pyreadstat, если они установлены, иначе пропускается). Проверка типов: `npm run typecheck`.

## Установка через Docker

```bash
git clone https://github.com/backstab1/LabSurvey.git surveylab && cd surveylab
cp .env.example .env && nano .env       # ADMIN_PASSWORD; без HTTPS — COOKIE_SECURE=0
mkdir -p data && sudo chown 1000:1000 data   # сервис в контейнере работает от пользователя node (uid 1000)
docker compose up -d --build
```

Данные, резервные копии и секрет сессий лежат в `./data`. Обновление: `git pull && docker compose up -d --build`.

## Установка на VPS (Ubuntu)

```bash
# Node.js 24
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt install -y nodejs git

git clone https://github.com/backstab1/LabSurvey.git /opt/surveylab
cd /opt/surveylab
npm ci
npm run build
cp .env.example .env && nano .env      # ADMIN_PASSWORD, NODE_ENV=production
```

Служба systemd `/etc/systemd/system/surveylab.service`:

```ini
[Unit]
Description=SurveyLAB
After=network.target

[Service]
WorkingDirectory=/opt/surveylab
Environment=NODE_ENV=production
ExecStart=/usr/bin/npm start
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data /opt/surveylab
sudo systemctl enable --now surveylab
```

Пока нет домена, сервис доступен по `http://<IP>:3000`. В этом режиме задайте в `.env` `COOKIE_SECURE=0`, иначе браузер не сохранит cookie входа без HTTPS. Когда появится домен, поставьте nginx с HTTPS (certbot), проксируйте на `127.0.0.1:3000`, задайте `TRUST_PROXY=1` (чтобы IP респондентов записывался правильно) и уберите `COOKIE_SECURE=0`.

Данные лежат в `data/surveylab.db`. Сервис сам делает резервные копии в `data/backups` (раз в `BACKUP_HOURS` часов, по умолчанию 24; хранится `BACKUP_KEEP` последних, по умолчанию 14). Список, скачивание и копия «сейчас» — кнопка «Резервные копии» на странице анкет. Для восстановления остановите сервис и замените `data/surveylab.db` скачанной копией. Копии лежат на том же диске — периодически скачивайте их или копируйте папку на другой сервер.

## Google Sheets

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект, включите **Google Sheets API**.
2. Создайте **сервисный аккаунт**, выпустите для него ключ JSON, положите файл на сервер (например, `/opt/surveylab/google-key.json`).
3. В `.env`: `GOOGLE_APPLICATION_CREDENTIALS=/opt/surveylab/google-key.json`, перезапустите сервис.
4. Откройте нужную таблицу на **редактирование** для email сервисного аккаунта (он показан во вкладке «Данные» анкеты).
5. Во вкладке «Данные» вставьте ссылку на таблицу и нажмите «Полная синхронизация». Если включено «Дописывать каждого нового респондента», новые анкеты будут добавляться автоматически. Если структура столбцов изменилась, лист перезаписывается целиком.

## Уведомления в Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен запишите в `.env`: `TELEGRAM_BOT_TOKEN=...`, перезапустите сервис.
2. Добавьте бота в нужный чат или канал (в канале — администратором).
3. Во вкладке «Данные» анкеты → «Уведомления» укажите ID чата (например, `-1001234567890`) или `@имя_канала`, выберите события и нажмите «Отправить тест».

## Архитектура

```
shared/   формат анкеты, логика (условия, действия, переходы, пайпинг, перенос), проверка ответов, модель переменных выгрузки,
          перевод старых версий формата (migrate.ts)
          — один и тот же код работает в браузере и на сервере
server/   Fastify + node:sqlite; API прохождения (сервер — источник истины: проверяет ответы и решает, куда идти),
          API админки, выгрузки (xlsx, sav — собственная реализация без зависимостей), Google Sheets
web/      React: страница опроса /s/:id и админка /admin (конструктор, JSON, настройки, данные)
docs/     документация формата — её же копирует кнопка «инструкция для ИИ»
```

- Методы хранилища асинхронные (`server/db.ts`), поэтому переход на PostgreSQL затронет только этот файл.
- Сохранённые ответы очищаются от «брошенных веток»: если респондент вернулся назад и сменил путь, ответы на вопросы, которые он больше не видит, в выгрузку не попадут.
- При переопубликации незавершённые респонденты продолжают по новой версии; номер версии пишется в выгрузку.

## Дальше (заложено в формате и архитектуре)

- **Несколько вопросов на одном экране** — опция блока (формат это допускает: движок уже работает с «экранами»).
- **Серверные скрипты** (обработка после завершения, вебхуки, квоты) — будут выполняться на сервере в изолированной среде (isolated-vm). Клиентские хуки и действия уже работают.
- **Квоты** и **панель респондентов** — через скрытые переменные и параметры ссылки уже можно передавать ID панелиста и группы.
- **Многопользовательский доступ** с ролями (сейчас один общий вход команды).
- **Генерация анкеты ИИ прямо в сервисе** — подключение LLM на ваш выбор; формат и валидатор уже готовы.
- Логотип и фирменные цвета — сейчас через CSS анкеты.

## Безопасность

- Скрипты анкет выполняются в браузере на том же домене, что и админка. Писать скрипты может только команда; не вставляйте код из непроверенных источников.
- Сервер всегда сам проверяет ответы, поэтому скрипты не могут записать некорректные данные в обычные вопросы.
